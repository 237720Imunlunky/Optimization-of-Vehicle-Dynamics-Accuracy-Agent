# 项目可行性验证报告

## 当前结论

项目链路已经可行并完成第一版落地：BLF 数据可由现有 DBC 解码，统一 CSV 可与 CarSim 输出逐工况比较，
LLM Agent 可按安全边界生成候选并执行多轮 CarSim 闭环评价。当前正式验收门槛由根目录 `config.json`
统一管理，纵向动力学输出数据精度要求为 80%。

## 当前已验证结果

1. 18 份实车 BLF 已完成解码，当前有效目录为 `输出/解码CSV_单位修正`。
2. 加速工况使用每条实车控制 Trace 独立仿真；滑行工况严格保留 50->30 km/h，当前采用舒适模式、N 挡、零油门、零制动、零回收。
3. 滑行第 3 次（窗口内有制动）和第 6 次（最高有效车速不足 50 km/h）已从当前数据集排除，第 5 次作为验证样本。
4. 当前正式基线位于 `输出/正式联合基线/当前配置基线`，综合精度 91.65%，正式门槛 80%，判定通过。
5. 当前 Agent 最优状态位于 `输出/LLM参数优化Agent` 下最新有效时间戳目录，综合精度约 93.81%，判定通过。
6. 控制输入闭环证据位于 `输出/动力总成修正/当前配置模型` 和 `输出/滑行工况审计/当前配置审计`，已确认油门信号能够分级进入模型，主要偏差来自 CarSim 动力学/动力系统响应差异。

## 配置与运行边界

- 评价阈值、权重、数据划分、滑行条件和 Agent 迭代策略只读取项目根目录 `config.json`。
- `llm_optimizer/config/parameter_registry.json` 只定义参数注册和 CarSim 绑定，不承担运行阈值配置。
- API 密钥只保存在 `Agent交互界面/config/llm_api.local.json`，不写入公共配置或日志。
- 修改 `config.json` 后，已有 Agent 状态会通过配置指纹判定是否需要重新生成基线；不得将不同口径的结果混合比较。

## 输出目录规则

正式结果只使用带“当前配置”的目录名；参数扫描、视觉验收和 Agent 时间戳目录属于过程证据，不能当作正式基线。
所有输出子目录应包含 README，说明文件作用和运行方式。

## 下一步

继续使用交互界面执行候选生成和 CarSim 闭环评价；当修改评价口径或滑行策略时，先重新运行正式基线，再启动 Agent 续跑。
